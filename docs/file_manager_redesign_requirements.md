# ファイラー再設計 要件定義書

最終更新: 2026-05-08

## 0. 本書の位置付け

本リポジトリのファイラーは、Phase 1〜5 の「UI モダナイゼーション」（`docs/ui_modernization_plan.md`）でテーマトークン・余白・アイコン・Mica 適用などの**外観**については一定の到達点に達した。一方、ファイラーとしての**最低限の機能性・操作性・視認性**には未充足の領域が残っており、ユーザーから「列幅が保存されない」「左右ペインが同期しない」「処理後にツリー位置がずれる」等の指摘も入っている。

本書は、これら「ファイラーとして当然備えているべき水準」を 2026 年現在のデスクトップファイラーの一般的な期待値に合わせるための**要件**を定義する。実装可能な仕様および段階計画は別ドキュメント（`file_manager_redesign_spec.md` / `file_manager_redesign_implementation_plan.md`）にて扱う。

## 1. 背景と目的

### 1.1 背景

- 既存仕様書 `docs/仕様書.md` は初期構想を残しているが、フォーマットが旧く、拡張機能との関係や受け入れ基準が曖昧。
- `docs/要件定義.md` は別プロジェクト（ニュース統合プラットフォーム）の内容で、本ファイラーの要件を表していない。
- UI モダナイゼーション（Phase 1〜5）はテーマと密度の刷新が中心で、**操作の流暢さ**（キーボード操作、状態同期、エラー復帰）には踏み込んでいない。
- Web 上の動向（Files App / OneCommander / Directory Opus 等）と比較すると、本ファイラーには「タブ」「パンくずアドレスバー」「ファイルプロパティダイアログ」「貼り付け」といった**標準機能の欠落**がある。

### 1.2 目的

「**最低限のファイラーとして十分に使え、視認性と操作性に妥協がない**」状態に到達させる。具体的には次の三本柱を満たすことを目標とする。

1. **機能性**: 一般的なデスクトップファイラーが備える基本操作（コピー / 切り取り / 貼り付け / プロパティ / アドレス入力 / 戻る進む / リフレッシュ）を欠落なく揃える。
2. **操作性**: マウス・キーボードどちらでも完結でき、操作後に状態が破綻しない（ペイン同期、選択維持、フォーカス復帰）。
3. **視認性**: 高密度かつ階層が読み取れるレイアウト、十分なコントラスト、状態の明示、エラーや進捗のフィードバック。

### 1.3 スコープ

| 区分 | 含む | 含まない |
| --- | --- | --- |
| OS | Windows 10/11 を主、Linux/macOS は best-effort | モバイル、Web |
| ペイン | 左ペイン（ツリー）／右ペイン（リスト）／プレビュー | 左右独立 2 ペイン操作（dual-pane）は次期検討 |
| ファイル種別 | ローカルファイルシステム | クラウド（OneDrive / Google Drive 等）、FTP/SFTP は対象外 |
| 国際化 | 日本語 UI を主、英語は将来検討 | 多言語切替機構の実装 |

## 2. ユーザー像とユースケース

### 2.1 想定ユーザー

| ペルソナ | 主な用途 | 期待値 |
| --- | --- | --- |
| **動画整理ユーザー**（既存主用途） | 大量の動画ファイルの整理・重複検出・サムネイル確認 | 動画系拡張機能とのスムーズな連携、リネーム後も状態維持 |
| **作業フォルダ往復ユーザー** | 開発・ドキュメント作業で複数フォルダを行き来 | パンくず／戻る進む／タブ（将来）／キーボード操作 |
| **キーボード派ユーザー** | マウスを極力使わない | 主要操作のショートカット、フォーカス可視化、Tab 巡回 |

### 2.2 主要ユースケース（最低限）

UC-1. **フォルダ閲覧**: ドライブを選び、ツリーから目的フォルダへ降りる／登る。
UC-2. **アドレスバーで直接ジャンプ**: パスを貼り付けて Enter で移動。
UC-3. **戻る / 進む**: 直前のフォルダへ戻る、再び進む。
UC-4. **ファイルを開く**: ダブルクリックまたは Enter で関連付けアプリを起動。
UC-5. **基本操作**: 新規フォルダ作成、リネーム、削除、ゴミ箱移動。
UC-6. **コピー＆ペースト**: クリップボードを介して別フォルダへコピー／移動。
UC-7. **ドラッグ＆ドロップ**: 左ペインの目的フォルダへドロップしてコピーまたは移動。
UC-8. **ファイル絞り込み**: 検索ボックスにキーワードを入力してフィルタ。
UC-9. **表示制御**: 列の表示／非表示、列幅、並び順の調整（次回起動でも保持）。
UC-10. **プロパティ確認**: 1 ファイル選択でサイズ・日付・属性などを参照。
UC-11. **状態同期**: 操作のたびにツリー（左）とリスト（右）が同じパスを示す。

### 2.3 既存の独自ユースケース（維持必須）

UC-X1. 動画ダイジェストの自動／手動表示。
UC-X2. 重複動画検出（サイズ／ファイル名類似性）。
UC-X3. ディスク使用量分析（円グラフ）。
UC-X4. ファイル検索（SQLite インデックス）。
UC-X5. ファイル名翻訳。

## 3. 機能要件

優先度は **MUST**（必須）／**SHOULD**（強く推奨）／**MAY**（あれば良い）。

### 3.1 ナビゲーション

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FN-1 | アドレスバーは**パンくず**形式で各セグメントをクリック可能にする。表示幅を超えるパスは省略表示し、左クリックで省略部のドロップダウンを開く | SHOULD |
| FN-2 | アドレスバーをクリックまたは `Ctrl+L` でテキスト編集モードに切り替わる。Enter で確定、Esc でキャンセル | MUST |
| FN-3 | 戻る／進むボタンを履歴の有無に応じて自動で有効化／無効化する（既に実装済み、維持） | MUST |
| FN-4 | `Alt+←` / `Alt+→` / `Alt+↑` でそれぞれ戻る／進む／親フォルダ | MUST |
| FN-5 | `Backspace` で親フォルダに移動（リスト編集中は除く） | SHOULD |
| FN-6 | ドライブボタンクリックでルートに移動。同時にツリーもそのドライブに切り替わる（実装済み、維持） | MUST |
| FN-7 | アドレスバーが無効パスを受け取った場合、アドレスを直前の有効値に戻し、エラーをステータスバーに 3 秒だけ表示する | SHOULD |

### 3.2 ファイル操作

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FO-1 | コピー (`Ctrl+C`) / 切り取り (`Ctrl+X`) / 貼り付け (`Ctrl+V`) を**実装する**。現在の `copy_selected_files` / `paste_files` は no-op のため要修正 | MUST |
| FO-2 | 切り取り中のアイテムは半透明で表示し、貼り付け後に元アイテムを削除する | SHOULD |
| FO-3 | リネーム (`F2`)、削除 (`Delete`)、ゴミ箱送り (`Shift+Delete` または明示ボタン) | MUST |
| FO-4 | 新規フォルダ作成 (`Ctrl+Shift+N`) | MUST |
| FO-5 | 全選択 (`Ctrl+A`) / 反転 (`Ctrl+I`) | SHOULD |
| FO-6 | OS のクリップボードと相互運用できる（Explorer でコピー → 本アプリで貼り付け、その逆も）。MIME `text/uri-list` および Windows の `CF_HDROP` を扱う | SHOULD |
| FO-7 | ドロップ操作はモディファイヤキーで動作切替: 既定はコピー、`Shift` で移動、`Alt` でショートカット（後者は MAY） | SHOULD |
| FO-8 | 同名衝突時はダイアログで「上書き／スキップ／別名で保存／キャンセル」を選択可能 | SHOULD |
| FO-9 | 大量ファイル（>1000 件）の操作は進捗バー＋キャンセル可能なバックグラウンド処理 | SHOULD |

### 3.3 表示・並び替え

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FD-1 | 列幅を変更すると即座に永続化し、再起動後も復元される（実装済み、維持） | MUST |
| FD-2 | 列の並び順を D&D で変更可能。並び順も永続化する | SHOULD |
| FD-3 | 列の表示／非表示はヘッダー右クリックで切替可能（実装済み、維持） | MUST |
| FD-4 | ソートは列ヘッダクリックで昇降切替。複数キー指定（Shift+Click）は MAY | MUST |
| FD-5 | 表示モード（リスト／アイコン／詳細）を切り替え可能。次回起動時に復元（実装済み、維持） | MUST |
| FD-6 | 詳細表示の行高は **24px** を既定とし、設定でコンパクト（22px）／ノーマル（24px）／ゆとり（28px）の 3 段階を選べる | SHOULD |
| FD-7 | 隠しファイル表示の ON/OFF（実装済み、維持） | MUST |
| FD-8 | フォルダはサイズ 0 ではなく `--` あるいは「フォルダ内項目数」を表示する | SHOULD |

### 3.4 検索とフィルタ

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FS-1 | ツールバーの検索ボックスは現在表示中のフォルダに対するインクリメンタルフィルタとする（実装済み、維持） | MUST |
| FS-2 | 外国語ファイル名フィルタの ON/OFF（既存独自機能、維持） | MUST |
| FS-3 | 高度な検索（再帰的に名前／サイズ／更新日で絞り込み）は別ダイアログ（実装済み、維持） | MUST |
| FS-4 | フィルタ適用中はリストヘッダー右側に件数バッジ（例: `12 / 384 件`）を出す | SHOULD |

### 3.5 プレビュー

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FP-1 | 動画ファイル選択時にダイジェストサムネイルをプレビューペインに表示（実装済み、維持） | MUST |
| FP-2 | 画像ファイル選択時にプレビュー画像を表示する（**新規**） | SHOULD |
| FP-3 | テキストファイル（≤256 KB）選択時に冒頭をプレビュー表示する（**新規**） | MAY |
| FP-4 | プレビューペインはトグルボタンまたはショートカット（`Ctrl+P`）で表示／非表示を切替できる | SHOULD |

### 3.6 ペイン同期と状態保持

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FY-1 | リスト側で表示中のパスとツリー側の選択は**常に**一致する（実装済み、維持＋強化） | MUST |
| FY-2 | リネーム・削除・移動・コピー・貼り付け・ゴミ箱送り・新規作成のいずれの後でも、ツリー選択がリスト位置と一致する | MUST |
| FY-3 | ファイル操作中に元のフォルダ自体が消失した場合、親フォルダへ自動的にフォールバックする | SHOULD |
| FY-4 | 終了時に最後のパス・スプリッタ位置・列幅・列順・列表示・テーマ・アクセント・表示モード・隠しファイル設定を保存し、起動時に復元する | MUST |

### 3.7 ファイル情報

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FI-1 | 「プロパティ」ダイアログ（`Alt+Enter`）でサイズ・更新日時・作成日時・属性・パス・拡張子・タイプを表示する（**新規**） | SHOULD |
| FI-2 | 動画ファイルでは尺・解像度・FPS をプロパティに含める（既存メタデータを流用） | SHOULD |
| FI-3 | 複数選択時のプロパティは合計サイズ・点数・種別内訳を集計表示する | MAY |

### 3.8 タブとマルチ表示

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FT-1 | タブで複数フォルダを切替表示できる（**新規**） | SHOULD |
| FT-2 | タブの追加 (`Ctrl+T`) / 閉じる (`Ctrl+W`) / 切替 (`Ctrl+Tab`, `Alt+1〜9`) | SHOULD |
| FT-3 | 終了時にタブ構成を保存し、起動時に復元する | SHOULD |

### 3.9 設定

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FC-1 | 既存の設定（テーマ・アクセント・色・列・表示モード等）を維持 | MUST |
| FC-2 | 新規: 行高プリセット（コンパクト／ノーマル／ゆとり） | SHOULD |
| FC-3 | 新規: アドレスバーの初期形態（パンくず固定／パス固定／自動） | MAY |
| FC-4 | 新規: ダブルクリック挙動（フォルダのみ降りる／ファイルも開く） | MAY |

## 4. 非機能要件

### 4.1 操作性

| ID | 要件 | 評価方法 |
| --- | --- | --- |
| NO-1 | キーボードのみで主要ユースケース（UC-1〜UC-11）を完遂できる | 手動テスト＋自動テスト |
| NO-2 | フォルダ切替は一覧 1,000 件以下なら**ローカル SSD で 200 ms 以内**にリスト表示開始 | 計測（後述） |
| NO-3 | 行のホバー反応は**16 ms 以内** | 体感 |
| NO-4 | 全操作の対象（選択中のアイテム）は視覚的に識別できる。どこにフォーカスがあるか常に分かる | 手動 |
| NO-5 | エラーは**モーダル乱立を避け**、軽微なものはステータスバーまたはトーストで通知。重大なものだけダイアログ | 手動 |

### 4.2 視認性

| ID | 要件 | 評価方法 |
| --- | --- | --- |
| NV-1 | 本文と背景のコントラスト比は **WCAG 2.1 AA（4.5:1）以上** | 単体テスト（トークン色） |
| NV-2 | UI 要素（ボタン枠、入力枠）は **3:1 以上** | 単体テスト |
| NV-3 | フォーカスリングはアクセント色で **2px 以上**、隣接領域とのコントラスト比 3:1 以上 | 手動 |
| NV-4 | 行高は既定 24px、最小 22px、最大 28px。文字サイズは 12〜14px の可変 | 設定とトークン |
| NV-5 | 「選択」「フォーカス」「ホバー」「無効」の 4 状態を**色だけでなく**形（ボーダー・アイコン）でも識別可能 | 手動 |
| NV-6 | 進捗・処理中状態は**プログレスバーまたはスピナー**で表す。全画面ブロックは 1 秒以内なら出さない | 手動 |
| NV-7 | アクセントカラーが極端な色でも前景・選択背景のコントラストを自動補正する（既存の `_derive_accent_tokens` を強化） | 単体テスト |

### 4.3 パフォーマンス

| ID | 要件 |
| --- | --- |
| NP-1 | 10,000 件のフォルダでも UI スレッドが **5 秒以上**ブロックされない |
| NP-2 | サムネイル等の重い処理は別スレッドで実行（既存 `QThreadPool` を維持） |
| NP-3 | 設定書き込みはアイドル時にまとめてフラッシュ（書き込み回数を 1 操作 1 回以内に） |

### 4.4 互換性・移行性

| ID | 要件 |
| --- | --- |
| NC-1 | 既存の `QSettings("FileManager","Settings")` キーを破壊しない。新キーは旧キーと共存させる |
| NC-2 | 既存ユーザーの `last_path` などは引き続き有効 |
| NC-3 | 既存独自機能（動画ダイジェスト・重複動画・ディスク分析・翻訳）の API シグネチャを変更しない |
| NC-4 | 既存テスト（`tests/test_button_actions.py` 等）はすべて継続して通過する |

### 4.5 アクセシビリティ

| ID | 要件 |
| --- | --- |
| NA-1 | すべての主要ボタン・入力に **アクセシブル名**（QObject の `accessibleName`／`toolTip`）を設定 |
| NA-2 | OS の "Reduce motion" 設定に追従し、必要時はアニメーションを無効化 |
| NA-3 | フォントスケール 1.0 / 1.15 / 1.3 に対応（既存設計の維持） |

### 4.6 信頼性

| ID | 要件 |
| --- | --- |
| NR-1 | ファイル操作中の例外で UI が落ちない（try/except で捕捉、ユーザーに通知） |
| NR-2 | 設定値が壊れていても起動できる（キー欠落時はデフォルトに戻す） |
| NR-3 | ファイル操作（移動・コピー）はトランザクション境界を明示し、失敗時に途中結果を残しても**復旧可能なメッセージ**を表示する |

## 5. 制約条件

- **言語／GUI 基盤**: Python 3.13 / PySide6 6.5+ を維持。
- **依存追加は最小限**: `qtawesome`, `winshell`, `send2trash` は既導入。新規パッケージ追加が必要な場合は要相談。
- **OS**: Windows 10 22H2 以降を主たるターゲット。Linux／macOS は機能縮退で良い（Mica は無効、ゴミ箱は send2trash）。
- **フォント**: Windows 11 では Segoe UI Variable、それ以外は Yu Gothic UI／Meiryo にフォールバック。
- **CLAUDE.md ルール準拠**: UI テキスト・コメントは日本語、`QSettings("FileManager","Settings")`、エラー通知は QMessageBox（重大時のみ）。

## 6. 受け入れ基準（Definition of Done）

機能性・操作性・視認性ごとに定義する。各項目はチェック可能な形に書く。

Phase A〜C の MUST 範囲で満たす基準を **MVP DoD**、Phase D 以降の SHOULD/MAY を含めて満たす基準を **Full DoD** とする。

### 6.1 機能性

- [ ] **コピー / 切り取り / 貼り付け**が動作し、Explorer との相互運用が可能
- [ ] **ファイルプロパティ**ダイアログが Alt+Enter で開く
- [ ] **アドレスバー**が `Ctrl+L` で編集可能（MVP）。パンくず表示は Full DoD
- [ ] **タブ切替**が `Ctrl+Tab`、追加が `Ctrl+T`、閉じるが `Ctrl+W` で動く（Full DoD）
- [ ] **画像プレビュー**が選択時に表示される（Full DoD）

### 6.2 操作性

- [ ] **キーボードのみ**で UC-1〜UC-11 を完了できる
- [ ] **`F2`/`Delete`/`Ctrl+C`/`Ctrl+X`/`Ctrl+V`/`Ctrl+A`/`Ctrl+L`/`Alt+Enter`/`Backspace`** がすべて動作
- [ ] ファイル操作後、左ペインのツリーがリストと一致する
- [ ] アドレスバーに無効パスを入れた場合、直前の有効値に戻りエラーがステータスバーに表示される

### 6.3 視認性

- [ ] 本文 4.5:1、UI 3:1 のコントラストを満たす（自動テスト）
- [ ] フォーカスがどこにあるか目視で常に分かる
- [ ] ステータスバーに「選択件数 / 合計サイズ / 現在パス」が表示される
- [ ] 進捗バーが大量操作時にきちんと出る
- [ ] 行高 / 列幅 / 列順 / 列表示が次回起動時に復元される

### 6.4 互換性

- [ ] 既存テスト 49 件以上が継続パス
- [ ] 既存ユーザーの設定が破壊されない（マイグレーション不要）

## 7. リスクと前提

| リスク | 影響 | 緩和策 |
| --- | --- | --- |
| クリップボード経由の貼り付けは Qt 単独では Explorer と完全互換を取りにくい | コピー／貼り付けの相互運用に難 | `QMimeData` の `urls`/`data("application/x-qt-windows-mime;value=...")` で対応。完全互換を Phase 2 のみ MUST、それ以外は SHOULD |
| パンくずアドレスバーは PySide6 標準にないため自前実装 | 工数増 | `QLineEdit` 内に `QToolButton` を配置するハイブリッドで段階導入 |
| タブ実装は内部状態管理が大きい | 工数大 | Phase D に後置。MVP（最低限）からは外す |
| ドラッグ＆ドロップで OS 間の挙動差 | コピー/移動の判定が割れる | 既存の `_prompt_drop_operation` ダイアログを保つ |
| 既存テストの geometry assert が壊れる可能性 | リグレッション | 行高は QSS 経由のみで変更、widget の直接サイズ操作はしない |

| 用語 | 定義 |
