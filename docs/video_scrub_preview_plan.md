# 動画内容を最短で把握する「スマートスクラブ・プレビュー」実装計画

最終更新: 2026-05-16
対象ブランチ: `feature/video-scrub-preview`

---

## 1. 背景と問題提起

現状の動画把握フローは下記の 2 系統が併存しているが、いずれも「動画の構造を瞬時に理解する」には至っていない。

| 機能 | 実装 | 体感問題 |
|------|------|----------|
| マウスオーバーサムネイル表示 | `file_manager.py` | 生成負荷が高くチラつく。1ファイルにつき毎回 OpenCV を回すため重い |
| 動画ダイジェスト（6枚静止画） | `video_digest.py` | 等間隔抽出のため「シーンの切れ目」を外す。一覧性が低く、内容把握に時間がかかる |

2025 年の業界標準（YouTube, Plex, Netflix）では、**「シークバー上を滑らせて内容を即座に把握する」** 体験が不可欠であり、本プロジェクトでもこれを導入する。

---

## 2. ゴール

**選択中の動画の内容を、3 秒以内に構造レベルで把握できる UI** を提供する。

- **TTFI**（Time To First Insight）: 動画選択から「内容の理解」まで。目標 ≤ 3 秒。
- **操作性**: クリック不要、マウス移動（スクラブ）のみで完結。
- **効率**: FFmpeg keyframe seek + I-frame 限定抽出により、既存 OpenCV 方式の 3 倍以上の速度を目指す。

---

## 3. 採用手法：スマートスクラブ・プレビュー

### 3.1 シーン境界検出（PySceneDetect AdaptiveDetector）

**等間隔 6 枚を廃止**し、意味のあるシーンの切れ目からキーフレームを選ぶ。

- アルゴリズム: `AdaptiveDetector`（rolling average により急激な変化を検知。カメラの動きに強い）
- 構成: 
  - 短〜中尺（< 30 分）: シーン境界検出を実行。
  - 長尺（≥ 30 分）または検出失敗時: 等間隔サンプルへフォールバック。
- 抽出枚数: 4 〜 12 枚（動画の密度に応じて動的に決定）。

### 3.2 FFmpeg による高速 I-frame 抽出

OpenCV の `CAP_PROP_POS_FRAMES` は低速なため、**FFmpeg の input-seeking (`-ss` を `-i` の前に配置)** に切り替える。

- コマンド例: `ffmpeg -ss {timestamp} -i "{path}" -frames:v 1 -q:v 3 -f image2pipe -`
- 高速化の鍵: `ffprobe` であらかじめ I-frame のタイムスタンプ一覧を取得し、その中からシーン境界に最も近い点を選択して抽出する。
- フォールバック: FFmpeg 未検出環境では既存の OpenCV 経路を使用。

### 3.3 ホバースクラブ UI

右ペインにタイムラインバーを持つプレビューウィジェットを配置する。

- **スナップ表示**: マウス位置に対応する「最も近い抽出済みフレーム」を瞬時に表示。
- **シーンマーカー**: シークバー上にシーンの切れ目を縦線で表示。
- **レスポンス**: メモリキャッシュを活用し、スクラブ時のレイテンシを 50ms 以下に抑える。

### 3.4 スマートクリップ・ループ（Animated WebP）

抽出したキーフレームを 0.4 秒間隔で繋いだ animated WebP をバックグラウンドで生成し、自動ループ再生する。これにより、ユーザーがスクラブ操作をしなくても内容が受動的に飛び込んでくる体験を作る。

## 4. 既存実装との統合方針

| 既存モジュール | 変更内容 |
|------|------|
| `video_digest.py` | 汎用的な I-frame 抽出ロジックを追加。既存の等間隔ロジックはフォールバックとして残す。 |
| `video_thumbnail_preview.py` | `VideoScrubPreview` ウィジェットに置換。既存の `VideoThumbnailPreview` は互換性のために内部にラップするか、設定で切り替え可能にする。 |
| `video_digest_cache.py` | 新しい抽出方式用にキャッシュキーのプレフィックスを `scrub_v2_` に更新。 |
| `file_manager.py` | 選択変更時のプレビュー更新イベントを、新ウィジェットの `display_video()` に接続。 |

## 5. 実装タスク

### Phase 1: 高速バックエンド実装
1. `src/file_manager/video_keyframes.py` 新設
   - `FFmpeg` / `ffprobe` の有無をチェックするユーティリティ。
   - I-frame タイムスタンプ取得機能。
   - `ffmpeg` を用いた並列抽出（`ThreadPoolExecutor` を使用）。
2. `src/file_manager/scene_detection.py` 新設
   - `PySceneDetect` ラッパー。依存関係がない場合はダミーを返す。
3. `requirements.txt` 更新: `scenedetect>=0.6.7` 追加。

### Phase 2: UI ウィジェット開発
4. `src/file_manager/video_scrub_preview.py` 新設
   - `QSlider` を継承したカスタムシークバー（シーンマーカー描画）。
   - `QMovie` による Animated WebP 再生対応。
   - マウスホバー位置からタイムスタンプへの変換と、最寄りフレームのスナップ表示ロジック。
5. 非同期ワーカ `ScrubPreviewWorker` の実装（抽出・生成・キャッシュ保存）。

### Phase 3: 統合と洗練
6. `file_manager.py` への組み込み。
7. 設定画面 (`settings_dialog.py`) への項目追加。
   - プレビューモード選択: 「オフ / 静止画 / スクラブ（推奨）」
   - FFmpeg パスの手動設定オプション。
8. キャッシュ管理の最適化。

## 6. リスクと対策

| リスク | 対策 |
|--------|------|
| FFmpeg がインストールされていない | OpenCV による等間隔抽出にフォールバック。設定画面で FFmpeg インストールを推奨するリンクを表示。 |
| 大容量動画でのシーン検出遅延 | 検出が完了するまで「等間隔の暫定フレーム」を表示し、バックグラウンドで差し替える。 |
| キャッシュによるディスク圧迫 | キャッシュサイズの上限（デフォルト 500MB）を設け、LRU 方式で自動削除。 |
| 高解像度動画での CPU 負荷 | 抽出サイズを 320x180 固定にし、抽出枚数に上限（12枚）を設けることで抑制。 |
